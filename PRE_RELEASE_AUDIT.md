### Чек-лист по направлениям аудита

**1. Защита данных пользователя**
- [x] Токены/JWT/куки **не используются и не хранятся** — программа не авторизуется нигде; DPAPI не требуется
- [x] Логи не содержат Authorization/Cookie/Bearer (проверено regex'ом по всем модулям)
- [x] Path Traversal закрыт: `sanitize_filename()` удаляет `\ / : * ? " < > |`, схлопывает пробелы, лимит 150 символов (запас до MAX_PATH 260 вместе с путём)
- [x] Command Injection исключён архитектурно: все `subprocess.run/Popen` — списки аргументов, `shell=True` отсутствует
- [x] TLS-верификация включена везде (нигде нет `verify=False`)
- [x] Хардкод секретов — отсутствуют

**2. Надёжность и edge cases**
- [x] try/finally на весь цикл: WebSocket закрывается, Chrome убивается, профиль и временные файлы удаляются
- [x] Временный файл `_tmp_<id>.m4a` создаётся ДО конвертации и удаляется в finally (битый MP3 в папке пользователя не остаётся: FFmpeg пишет в целевой файл, при ошибке возвращается M4A)
- [x] Worker-поток обёрнут в try/except, ошибки приходят в GUI как человекочитаемое сообщение
- [x] Race conditions исключены: одна загрузка за раз (флаг `_busy`), лог пишется под `threading.Lock`
- [x] **Новое в v3.1:** PID-файл `%TEMP%\sunodl_cdp.pid` — при следующем запуске сиротский Chrome (от убитого процесса) убивается автоматически
- [ ] ⚠️ Нет retry при сетевых сбоях (одна попытка) — принято сознательно: ошибка сопровождается полной диагностикой в логе; повтор пользователем дешевле таймеров

**3. Совместимость Windows x64 / AV-friendly**
- [x] Запись только в разрешённые места: выбранная папка пользователя, `%TEMP%`, `%LOCALAPPDATA%\SunoDownloader` (лог)
- [x] **Новое в v3.1:** лог перенесён из директории .exe в `%LOCALAPPDATA%\SunoDownloader\` — если пользователь положит .exe в Program Files, запись лога не упадёт от отсутствия прав
- [x] Все subprocess с `CREATE_NO_WINDOW` (никаких консольных вспышек)
- [x] Unicode: имена файлов пишутся через WinAPI Python (UTF-16LE нативно), кириллица/эмодзи в названиях работают; логи — UTF-8
- [x] Нет LoadLibrary/ctypes/реестра/обфускации/dynamic exec
- [x] Внешние соединения только с целевыми доменами: suno.com, usesuno.com, cdn*.suno.ai + 127.0.0.1 (CDP)
- [x] **Новое в v3.1:** кнопка «📄 Журнал» в GUI открывает файл лога в проводнике (для диагностики)

**4. Качество кода**
- [x] USER_AGENT, таймауты, порты — константы/параметры методов
- [x] **Новое в v3.1:** удалены мёртвые зависимости `mutagen` и `pillow` (не импортируются нигде) — меньше поверхность для CVE
- [x] Актуальные версии зависимостей (customtkinter 6.x, requests 2.34, pyinstaller 6.22)
- [x] Нулевые bare except во всех модулях

## 2. Блокеры и критические баги (исправлено в v3.1)

### [High] Сиротский процесс Chrome после принудительного завершения
- **Где:** `downloader.py`, `process()`
- **Сценарий сбоя:** Пользователь дважды кликает «Закрыть окно» или антивирус убивает .exe во время загрузки → блок `finally` не выполняется → скрытый Chrome (`--window-position=-32000,-32000`) висит в памяти бесконечно, порт CDP занят, профиль в `%TEMP%` не чистится. При следующем запуске новый Chrome не сможет занять порт.
- **Исправление (внедрено):** PID-файл `%TEMP%\sunodl_cdp.pid`. Записывается сразу после запуска браузера, удаляется в `finally`. При старте нового сеанса предыдущий PID читается и убивается `taskkill /F /T`.

### [Medium] Лог рядом с .exe → падение записи в Program Files
- **Где:** `logger.py`
- **Сценарий сбоя:** Пользователь копирует .exe в `C:\Program Files\Suno\` (типично для «установки») → запись `suno_downloader.log` молча падает (PermissionError глотается) → при обращении за диагностикой файла нет.
- **Исправление (внедрено):** Путь лога — `%LOCALAPPDATA%\SunoDownloader\suno_downloader.log` (всегда доступен для записи), плюс кнопка «📄 Журнал» в GUI показывает его в проводнике.

### [Low] Мёртвые зависимости mutagen/pillow
- **Где:** `requirements.txt`, `build.bat`
- **Сценарий:** Лишние пакеты увеличивают время сборки и поверхность атаки без функциональной пользы (ID3-теги делает FFmpeg, Pillow не используется).
- **Исправление (внедрено):** Удалены из requirements и проверок build.bat.

### [Low] Ложное отклонение 64-битного ffmpeg.exe (v3.0)
- **Где:** `build.bat`, шаг [5/8]
- **Сценарий:** Проверка PE-заголовка по неверному смещению отклоняла корректный ffmpeg → сборка блокировалась ложным «NOT a 64-bit binary».
- **Исправление (внедрено):** Проверка через библиотеку `pefile` (`pe.FILE_HEADER.Machine == 0x8664`) — надёжное чтение структуры PE.

## 3. Рекомендации по снижению детектов AV/SmartScreen

Код уже чистый (нет обфускации, ctypes, реестра, нестандартных HTTP-клиентов). Остались меры на уровне сборки:

1. **Кодированная подпись (code signing)** — главное средство против SmartScreen. Без подписи любой onefile-.exe с паттерном «запуск браузера + taskkill» помечается как «Неизвестный издатель». Сертификат EV/OV (~$100–400/год) убирает предупреждение полностью.
2. **Reputation** — Microsoft Reputations: чем больше людей запускают неподписанный exe без жалоб, тем реже SmartScreen срабатывает. Первые недели предупреждения возможны.
3. **Не менять флаги запуска Chrome** — `--remote-debugging-port` + `taskkill /F /T` легитимны, но именно они эвристически выделяются. Держать их неизменными, чтобы хеши/паттерны стабильны.
4. **Не вшивать ffmpeg.exe внутрь, если появятся проблемы** — альтернатива: дистрибутив из двух файлов (SunoDownloader.exe + ffmpeg.exe рядом). Onefile распаковывается в `%TEMP%` при каждом запуске — это сам по себе эвристический маркер; двухфайловая схема прозрачнее для EDR. Текущая схема onefile оставлена по требованию ТЗ.
5. **Приложить README/ANALYSIS.md к дистрибутиву** — повышает доверие и даёт пользователю ссылку на журнал при проблемах.
